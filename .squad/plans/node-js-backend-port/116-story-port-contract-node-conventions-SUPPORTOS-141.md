## Story Goal

Produce the two artefacts every later NODE story is measured against, before any Node code exists.

1. **`docs/api-contract.django.yaml`** — the Django API surface, generated from the live URLConf and committed as a **frozen reference snapshot**, with a header that says in the file itself that it is a port contract and not the live schema.

**Not in scope, and the executor must not start it:** scaffolding the NestJS project, `prisma db pull`, any `package.json`, any TypeScript file, the health endpoint. All of that is `NODE-1` (`SupportOs backlog.MD:1142-1148`). This story writes two documents, one Python management command with its test, and one tag — nothing else.

## Product rules (from story)

| | Current behaviour | New behaviour after this story |
|---|---|---|
| OpenAPI document | **Generated, never checked in** (`docs/BACKEND-ARCHITECTURE.md:122`). Produced on demand by `manage.py spectacular`, or served live at `/api/schema/`. | Unchanged **as the live schema**. One additional, named, documented artefact exists: `docs/api-contract.django.yaml`, a committed *port contract snapshot*. The rule is not repealed — a second exception is not licensed by this one. |
| When the snapshot changes | n/a | Only when the Django reference itself changes, and only by re-running `python manage.py freeze_api_contract`. **Hand-editing it is a defect**, and the header says so. |
| Node conventions | Do not exist. `CONVENTIONS.md` is Django + React only. | `CONVENTIONS-NODE.md` (`CONV-NODE`) exists and is referenced by ID from `NODE-1` onward, the same way `CONV` is. |
| Git tags | None — `git tag` prints nothing. | `django-baseline` marks the pre-port commit. |

## Implementation tasks

### 1 — Add the `freeze_api_contract` management command

**Create file: `backend/apps/core/management/commands/freeze_api_contract.py`**

`apps/core/management/commands/` already exists (it holds `seed_demo_data.py`), so no new package is needed at the `management/` level — **confirm `commands/__init__.py` is present** before adding the file, and create it if it is not.

The command exists for one reason: a snapshot generated by a bare `manage.py spectacular --file` carries no header, and the next person to regenerate it would silently drop a header added by hand. Generation and header must be the same operation.

```python
"""Freeze the Django API surface as the EPIC 18 port contract.

`docs/BACKEND-ARCHITECTURE.md` states the OpenAPI document is generated,
never checked in. This command writes the one documented exception:
`docs/api-contract.django.yaml`, the frozen reference the Node port
(EPIC 18, NODE-0) is diffed against by NODE-2's harness.

The header is written by this command rather than by hand, because a
hand-added header does not survive the next regeneration — and a snapshot
without its header is indistinguishable from the live schema, which is
exactly the confusion the "never checked in" rule exists to prevent.

Regenerate ONLY when the Django reference itself changes. See
CONVENTIONS-NODE.md and SupportOs backlog.MD EPIC 18.
"""
```

Behaviour, concretely:

- Default output path is `docs/api-contract.django.yaml`, resolved from `settings.BASE_DIR` — **not** a hardcoded relative path, so the command works from any working directory. Read `backend/config/settings/base.py` for what `BASE_DIR` actually anchors to before computing the path. Accept `--file` to override (used by the drift check in Verification Step 5).
- Delegate generation to `call_command("spectacular", file=<temporary path>)`. `--file` is the option `docs/BACKEND-ARCHITECTURE.md:150` already documents; do **not** invent other flags. Run `python manage.py spectacular --help` first — if that installed version lists a `--fail-on-warn` option, pass it too, so a schema that regressed to a W001/W002 (the state Story 104 fixed) fails the freeze instead of silently freezing a broken contract.
- Prepend a YAML comment header to the generated body and write the result to the output path. The header is a comment block, so the file stays a valid OpenAPI document that NODE-2's harness can parse unchanged:

```yaml
# ============================================================================
# PORT CONTRACT — NOT THE LIVE SCHEMA.
#
# A frozen snapshot of the Django API surface, committed as the acceptance
# spec for EPIC 18 (Node.js Backend Port). The live schema is generated on
# demand — `python manage.py spectacular`, or GET /api/schema/ — and is
# still never checked in (docs/BACKEND-ARCHITECTURE.md, Measured manifest).
# This file is the single, documented exception to that rule.
#
# Every 2xx body below is the WRAPPED form: `apps.integrations.schema.
# envelope_postprocessing_hook` nests each payload under `data` inside
# {success, data, error, meta}, and list endpoints carry `meta.pagination`
# from `apps.core.pagination.DefaultPageNumberPagination`.
#
# DO NOT EDIT BY HAND. Regenerate with:
#     python manage.py freeze_api_contract
# and only when the Django reference implementation itself changes.
#
# Generated from config/api_urls.py via drf-spectacular.
# Consumed by NODE-2's contract-diff harness.
# ============================================================================
```

- Print the resulting path and the path count to stdout on success (`self.stdout.write(self.style.SUCCESS(...))`), matching `sync_role_permissions.py`'s reporting style.
- **Do not** register a URL, a setting, or a Celery task. This command is run by a person, never by the app.

### 3 — Write `CONVENTIONS-NODE.md`

**Create file: `CONVENTIONS-NODE.md`** at the repo root, beside `CONVENTIONS.md`.

Open with a one-paragraph statement of what this document is and is not:

> `CONV-NODE` is the Node/TypeScript counterpart of [`CONVENTIONS.md`](CONVENTIONS.md) (`CONV`), for EPIC 18's port of the Django API. It **does not restate `CONV`** — naming, wire format, i18n, logging policy, auth model and permission vocabulary are unchanged and are cited by section number. It records only what is genuinely new because the runtime is different.

Then exactly these sections, each short and reference-based:

**1. The port rule.** Verbatim from `SupportOs backlog.MD:1258`: the port adds no product scope; a NODE story that introduces a new endpoint, a new response shape, a schema change or a frontend edit has stopped being a port. State that `docs/api-contract.django.yaml` is the acceptance spec, that NODE-2's harness is what enforces it, and who regenerates the snapshot and when (any change to the Django API surface, in the same change).

**2. The database is introspect-only.** Prisma is generated by `db pull` from the live database; **no migration command may ever run from the Node service.** Django migrations under `backend/apps/*/migrations/` (91 of them) remain the single source of schema truth for the whole epic. State explicitly that this rule is lifted **only** by NODE-12's retirement task, and not before. This is the Node counterpart of `docs/BACKEND-ARCHITECTURE.md`'s `makemigrations --check --dry-run` gate — name what replaces that gate: a check that the Node service contains no migration directory and no `prisma migrate` script.

**3. Module layout.** One NestJS module per business area, mirroring `backend/apps/` one-for-one: `accounts`, `agents`, `ai`, `communications`, `compliance`, `core`, `customers`, `integrations`, `knowledge_base`, `notifications`, `organization`, `portal`, `reports`, `sla`, `tickets`. Reference `backend/apps/README.md` for the "where does new code go" decision list rather than restating it, and carry over its one hard rule: **no top-level `services/`, `controllers/` or `utils/` package** — a business area owns its own files. Name the service root directory once and fix it: **`backend-node/`**, a sibling of `backend/` and `frontend/`. This is what `NODE-1`'s "scaffold the NestJS project beside the Django one" means concretely; NODE-1 must not re-decide it.

**4. The envelope is an interceptor, and there is exactly one.** A single global interceptor produces `{success, data, error, meta}`; **no controller builds its own response shape** — state this as a hard rule, because `CONV` § 11 enforces it structurally via `EnvelopeJSONRenderer` rather than by convention. Carry over the three behaviours verified in `backend/apps/core/renderers.py:14-24`:
   - a body that is already an envelope passes through untouched (pagination produces one directly);
   - `204` and `304` carry an **empty body**;
   - `PlainTextRenderer`'s exception — WhatsApp's `GET` webhook handshake echoes `hub.challenge` as a raw string and **must not** be enveloped (`backend/apps/core/renderers.py:27-52`).

   State the `meta.pagination` keys as fixed: `count`, `page`, `page_size`, `num_pages`, `next`, `previous`.

**5. The exception filter and the error-code map.** One global filter, one error shape. Give the mapping as a table taken from `backend/apps/core/exceptions.py` — do not paraphrase it:

| Source condition | HTTP | `error.code` | `error.fields` |
|---|---|---|---|
| DTO/validation failure | 400 | `validation_error` | `{field: [message]}`; non-field errors under `non_field_errors` |
| FK-protected delete | 400 | `validation_error` | single non-field message |
| Missing/invalid credentials | 401 | framework default code | `{}` |
| Authenticated, permission denied | 403 | framework default code | `{}` |
| No such resource, or one outside the caller's scope | 404 | framework default code | `{}` |
| Anything unrecognised | 500 | `internal_error` | `{}` |

   Plus: `error.request_id` is present whenever the failure happened inside a request; `error.debug` only when debug mode is on; **neither is a top-level key** — the four top-level keys are fixed.

**6. DTO validation.** Validation is declared on the DTO and applied by a global pipe, never hand-rolled in a handler. Wire keys stay `snake_case` end to end (`CONV` § 12) — **do not camelCase on the way in or out**; state that this means DTO property names are `snake_case` too, since renaming at the boundary is exactly what would break the frozen contract.

**7. Guard placement.** Guards are global and fail closed. Reference `CONV` § 22 for the permission vocabulary — the same 25 permission strings, read from the same `Role.permissions` rows. State the rule `CONV` § 23 already enforces on the Django side: **every route declares its permission; an undeclared route is denied, not allowed.** Scoping (department/branch, and portal owner-scoping) is a query-layer concern, not a handler concern — `NODE-3` builds it; this document fixes only the requirement that a handler must not be able to issue an unscoped query for a scoped model.

**8. Config validation.** Environment is parsed and schema-validated once at boot; the process refuses to start on a missing or malformed required variable. Reference `CONV` § 9 rather than re-listing variables, and state that the Node service reads the **same** variable names as Django — a second naming scheme for the same values is a drift source.

**9. Logging and correlation id.** The Node middleware must reproduce `backend/apps/core/middleware.py:13-43` exactly: read an incoming **`X-Request-ID`**, generate one when absent, make it available for the whole request, and echo it on the response header. Log calls carry it without declaring it. Carry over two rules from `CONV` § 34 as-is: log `request.path`, **never** the full path with its query string (the inbound-email webhook authenticates with `?token=…`), and scrub by **key name** — `password|secret|token|api_key|authorization|credential|cookie|session` — never by guessing at value shapes.

**10. What this document does not cover.** Testing strategy, deployment, and the admin-surface replacement (NODE-11) are named as deliberately out of scope with their owning story, so a later reader does not mistake an omission for a decision.

Keep it to roughly one page of real content. If a section grows past a screen, it is restating `CONV` — cut it back to the reference.

## Edge Cases & Failure Modes

- **The venv does not exist.** `dev.ps1:21` expects `backend/.venv`; this checkout has none, and the system Python lacks `celery`, so `manage.py` dies at `config/celery.py:17` before Django even loads. Every command in this plan fails with that traceback until `HOW_TO_USE.md:300-303` is followed. This is the first thing to do, not a troubleshooting note.
- **The path count is not 131.** `docs/BACKEND-ARCHITECTURE.md:114` records 131, measured at an earlier commit; it was **not** re-measured while writing this plan, precisely because the venv is missing. Treat a mismatch as unresolved, not as a new baseline — reconcile it and update the manifest table in the same change (Task 2).
- **The generator emits W001/W002 warnings.** Story 104 drove these to zero. A reappearance means a view added since then is undocumented or mis-documented, and the frozen contract would encode that gap as the port's target. Fail the freeze rather than commit it — this is why Task 1 passes `--fail-on-warn` when the installed version offers it.
- **Someone hand-edits the frozen contract.** The header forbids it and Verification Step 5 detects it (regenerate to a temp file, diff). There is no runtime enforcement, and there should not be one — the file is deliberately outside the app.
- **The snapshot goes stale against a changing Django backend.** This is the exact failure `docs/BACKEND-ARCHITECTURE.md:122` warns about, now accepted deliberately for a bounded period. `CONVENTIONS-NODE.md` § 1 must say who regenerates it and when; NODE-2's harness reads the snapshot, so a stale snapshot surfaces as harness mismatches rather than as silence.
- **`PlainTextRenderer`'s WhatsApp handshake.** A Node interceptor that envelopes unconditionally returns JSON where Meta's webhook verification requires a bare string, and the channel silently stops verifying. `CONV-NODE` § 4 must name it; a generic "wrap everything" rule is wrong here.
- **204/304 with a body.** `EnvelopeJSONRenderer` returns `b""` for both (`renderers.py:19-21`). An interceptor that wraps `null` into `{"success":true,"data":null,…}` on a 204 changes the response for every delete endpoint in the contract.
- **Double-wrapped pagination.** `_is_enveloped` (`schema.py`) exists because a paginated response is *already* an envelope — `meta.pagination` is a sibling of `data` and cannot be added from outside. A Node interceptor without the same check buries `meta.pagination` inside `data` on every list endpoint, i.e. most of the 131 paths.
- **`SUPPORTOS-141` turns out to be `NODE-1`.** Then this plan is still the work that must happen first, but the tracker id in the filename and overview row is wrong. Correct the id; do not re-scope the story.
- **The `django-baseline` tag already exists remotely.** `git tag` is local-only here, so a tag could exist on `origin` without appearing. Run `git ls-remote --tags origin` before creating it, and do not move an existing tag.
