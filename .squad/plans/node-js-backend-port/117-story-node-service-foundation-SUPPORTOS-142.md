## Story Goal

Stand up an empty Node service that already answers in the product's own API shape, and give it typed access to the existing database without touching that database.

1. **A NestJS service at `backend-node/`** with schema-validated environment config, the response-envelope interceptor, the exception filter, pagination, and the correlation-id middleware — the five pieces every later NODE module reuses.
2. **A Prisma client generated from the live database** by `db pull`, with the generated `schema.prisma` committed, and a structural guard that no migration can ever run from this service.
3. **`GET /api/health/` answering byte-for-byte as Django does** — the first end-to-end proof that routing, config, database access and the envelope work together.

**Not in scope, and the executor must not start it:** any domain module (customers, tickets, accounts…), authentication, JWT, the permission guard, the scope layer, throttling, BullMQ, the WebSocket gateway, and the contract-diff harness. `NODE-2` builds the harness (`SupportOs backlog.MD:1150-1155`); `NODE-3` builds auth and scoping (`:1157-1165`). **A domain endpoint appearing in this story means the story was misread.**

**The envelope and error shapes must match the frozen contract byte-for-byte** — that is the intake's own constraint, and it is what makes this foundation reusable rather than something `NODE-3` has to re-litigate.

### 2 — Environment config, schema-validated, from one file

**There is exactly one `.env` for the whole port.** `CONV-NODE` § 8 requires the Node service to read the **same variable names** as Django; reading a *second file* holding the same `POSTGRES_*` values would recreate the drift that rule exists to prevent. **Create file: `backend-node/src/core/config/env.schema.ts`**

// beats two variables with the right ones and different values.
POSTGRES_DB        // required, string
POSTGRES_USER      // required, string
POSTGRES_PASSWORD  // required, string
POSTGRES_HOST      // default "localhost"

**Create file: `backend-node/src/core/config/config.module.ts`** — a global module wiring `@nestjs/config` with `envFilePath` pointing at `../backend/.env` (resolved from the service root, not the cwd) and the schema above as its validator. ### 4 — The four cross-cutting pieces

All under `backend-node/src/core/`, mirroring what `apps/core` holds today.

#### 4a — Correlation id middleware

**Create file: `backend-node/src/core/middleware/request-id.middleware.ts`**

Port `backend/apps/core/middleware.py` exactly:

- Read the `X-Request-ID` request header; adopt it **only** if it matches `/^[A-Za-z0-9._-]{8,64}$/`; otherwise generate one. A malformed id is **never** a 400.
- Make it available for the whole request via `AsyncLocalStorage` — the Node equivalent of Django's `ContextVar`, and the only thing that survives an `await` boundary correctly.
- **Echo `X-Request-ID` on every response**, always.
- Register it **first**, before everything except CORS, matching `MIDDLEWARE[0..1]` in `config/settings/base.py`.

Add an access-log line per request at INFO (WARNING at `>= 500`) that **skips `/api/health/`**, matching `SKIP_PATHS`. Log `req.path`, **never** the URL with its query string (`CONV` § 34 — the inbound-email webhook authenticates with `?token=…`).

#### 4b — Envelope interceptor

**Create file: `backend-node/src/core/interceptors/envelope.interceptor.ts`**

Register globally. Build the object literal in **exactly this key order** — `success`, `data`, `error`, `meta` — because Verification Step 7 is a byte comparison:

```ts
{ success: true, data: payload, error: null, meta: meta ?? null }
```

Three behaviours, each from `renderers.py:14-24` and each a live endpoint if missed:

1. A payload that is **already an envelope** passes through untouched. Mark enveloped payloads with a nominal type the pagination helper produces, rather than sniffing for a `success` key — `apps/core/envelope.py`'s `Envelope` class exists precisely so a payload that happens to contain `"success"` is not mistaken for a wrapped one.
2. **`204` and `304` return an empty body.** Not `{"success":true,"data":null,…}`.
3. A route may opt out entirely, for the WhatsApp `hub.challenge` handshake (`CONV-NODE` § 4). No such route exists in this story — build the opt-out, do not use it.

#### 4c — Exception filter

**Create file: `backend-node/src/core/filters/all-exceptions.filter.ts`**

One global filter, producing `{success: false, data: null, error: {code, message, fields}, meta: null}` with `error.fields` defaulting to `{}`. Map to the **12 codes in the table at Context item 9** — that table is the contract, not a starting point.

- Validation failures → `validation_error`, `fields` as `{field: [message, …]}`, non-field messages under **`non_field_errors`**.
- `error.request_id` is added from the `AsyncLocalStorage` id whenever one exists; `error.debug` (message + stack) **only when `DJANGO_DEBUG` is true**.
- Log unhandled errors at ERROR with `{http_path, http_method, exc_class}` as structured fields, matching `_internal_error_response`.
- An unrecognised exception is **`internal_error` / 500**, never an escaped stack trace.

**Localization:** Django translates error messages through `LocaleMiddleware` and `gettext` — `backend/locale/ar/` exists, and `"The submitted data is invalid."` has a real Arabic translation. **This story hardcodes the English strings and does not build a translation layer.** Record it as a known parity gap in `backend-node/README.md` so `NODE-2`'s harness can classify an `Accept-Language: ar` message diff as *expected-and-tracked* rather than as a new failure. Do not silently leave it undocumented.

#### 4d — Pagination

**Create file: `backend-node/src/core/pagination/paginate.ts`**

A helper returning an already-enveloped result carrying all six `meta.pagination` keys in order: `count`, `page`, `page_size`, `num_pages`, `next`, `previous`. Query params are **`page`** and **`page_size`**; `page_size` above `DRF_MAX_PAGE_SIZE` is **clamped, not rejected** (`README.md:611`). `next`/`previous` are absolute URLs built from the incoming request, as DRF builds them. No domain module uses it in this story — it exists so `NODE-4` does not invent its own.

### 5 — The health endpoint

**Create file: `backend-node/src/core/health/health.controller.ts`**

`GET /api/health/`, no authentication, no throttle. Call `prisma.$queryRaw\`SELECT 1\`` inside a `try`:

| Database | Body | Status |
|---|---|---|
| reachable | `{"status": "ok", "database": "ok"}` | **200** |
| unreachable | `{"status": "degraded", "database": "error"}` | **503** |

**Both go through the success envelope** — `success: true`, `error: null`, `meta: null`, even on the 503. This is not a mistake to correct: `HealthView` returns a `Response`, not an exception, so `EnvelopeJSONRenderer` wraps it as a success, and `test_health.py::test_health_reports_degraded_when_database_unreachable` asserts exactly that. A Node service that returns an error envelope on 503 has diverged.

Return the plain payload from the controller and let the interceptor wrap it. **Never build the envelope here** — `README.md:631` is explicit, and `HealthView` is its named reference implementation.

## Edge Cases & Failure Modes

- **`/api/health/` is not in the frozen contract.** `HealthView` carries `@extend_schema(exclude=True)` (`apps/core/views.py:71`), and `grep -n "health" docs/api-contract.django.yaml` returns nothing. The contract cannot verify this story's only endpoint — verification is a direct diff against running Django (Step 7). Do not "fix" the contract by un-excluding the view; that would add a path to a frozen snapshot to make a test easier.
- **A 503 health response is a `success: true` envelope.** Pinned by `test_health.py`. The instinct to return an error envelope on 503 is wrong here and would diverge on the one endpoint this story ships.
- **Envelope key order is load-bearing.** `apps/core/envelope.py` inserts `success`, `data`, `error`, `meta` in that order and `json.dumps` preserves it. A JavaScript object literal preserves string-key order too — so build it in the same order, or Step 7's byte diff fails on a difference nobody cares about semantically.
- **Trailing slashes.** All 131 contract paths end in `/`. Express 5 (NestJS 11) no longer treats `/x` and `/x/` as interchangeable by default. Getting this wrong fails every path simultaneously, and it will look like a routing catastrophe rather than a one-line config issue.
- **`DATABASE_URL` does not exist in this project.** Django reads discrete `POSTGRES_*` variables (`config/settings/base.py:125-135`). Composing the URL in the config layer is the only option that does not create a second source of truth for the same credentials; adding `DATABASE_URL` to `backend/.env` would mean two places to change a password and one of them silently stale.
- **`prisma db pull` will model Django's bookkeeping tables too.** 62 tables against 43 domain models. `django_migrations`, `django_content_type`, `auth_permission` and the `django_celery_beat_*` set will appear in `schema.prisma`. That is correct for an introspection and must not be trimmed by hand — a hand-trimmed schema stops being reproducible by `db pull`, which is the whole guarantee.
- **`prisma db pull` against a database mid-migration.** If Django migrations are applied while introspection runs, the committed schema captures a half-applied state. Run `python manage.py migrate --check` from `backend/` first, and re-run `db pull` after any Django migration for the rest of the epic.
- **A scaffolded `*.spec.ts` left in place violates `CONVENTIONS.md` § 16.** `nest new` creates them without asking. Deleting them is a task step, not cleanup.
- **Port 8001 is already claimed** by the Docker stack's backend (`README.md:1029`). 8002 is the first genuinely free port; picking 8001 breaks the documented "run both stacks at once" workflow in a way that only shows up for whoever uses Docker.
- **Arabic error messages are a known, deliberate parity gap.** Django localizes error strings via `gettext` and `backend/locale/ar/` has real translations. This story ships English only and records the gap. Undocumented, it would surface in `NODE-2` as a mysterious per-message diff under `Accept-Language: ar`.
- **`next`/`previous` pagination URLs embed the host and port.** Django on 8000 and Node on 8002 produce different absolute URLs for the same page. Expected; `NODE-2` compares shape and semantics, not generated identifiers or hosts (`SupportOs backlog.MD:1152`).
- **`/api/health/` is exempt from access logging** (`SKIP_PATHS`, `middleware.py:16`). A load balancer hits it on a timer forever; logging it buries every line that matters.

## Migration / Rollback

The service is **purely additive**: a new top-level directory, one line in `backend/.env.example`, one README row. Nothing in `backend/` or `frontend/` changes behaviour, and both stacks serve the same database concurrently by design.

**Rollback is `rm -rf backend-node/` plus reverting the two documentation lines.** No database state to undo — `db pull` reads and never writes, and `check:no-migrations` exists to keep that true.

**Half-applied state to watch:** an introspection committed *before* a later Django migration leaves `schema.prisma` describing a schema that no longer exists. It fails at Prisma client generation or at the first query, not silently — but re-run `npx prisma db pull` after any Django migration for the remainder of the epic.
